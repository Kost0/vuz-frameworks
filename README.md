# vuz-frameworks – трекер прогресса обучения

## Назначение

Приложение для планирования обучения и отслеживания прогресса по курсам и
темам. Консольная версия (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Возможности:

* просмотр списка курсов и информации о конкретном курсе в браузере;
* вход за конкретного студента по имени (без пароля) и страница «Мои курсы»
  с личным прогрессом;
* просмотр темы курса с текстом и списка пользователей, прошедших тему;
* отметка темы пройденной вошедшим студентом (прогресс сохраняется в JSON);
* просмотр прогресса пользователей по курсам и детальной карточки прогресса;
* (консоль) добавление курса, отметка темы пройденной, поиск курсов,
  фильтрация и сортировка по прогрессу;
* хранение данных между запусками в JSON-файлах.

## Используемые технологии

* Python 3.10+;
* Django 5.2 – веб-фреймворк;
* HTML – разметка страниц;
* CSS и Bootstrap 5.3 (через CDN) – оформление;
* pytest и pytest-django – автоматизированные тесты;
* flake8, autopep8, pyright (движок Pylance) – проверка качества кода.

## Предметная область

Основные сущности:

* `User` – пользователь системы;
* `Course` – учебный курс;
* `Theme` – тема курса;
* `Progress` – прогресс конкретного пользователя по конкретному курсу.

Связи между объектами:

```text
User
 └── Progress
      ├── User → пользователь
      └── Course → курс
                    └── Theme[] → темы курса
```

Один пользователь может изучать несколько курсов, поэтому у него может быть
несколько объектов `Progress`.

### Основные сущности

#### User

* атрибуты: `id`, `name`, `email`, `progresses`;
* методы: `add_progress()`, `get_progress()`, `__str__()`, `from_data()`,
  `to_data()`.

#### Course

* атрибуты: `id`, `name`, `themes`;
* методы: `add_theme()`, `get_theme()`, `get_theme_by_id()` (добавлен в ПР5),
  `calculate_progress()`, `__str__()`, `from_data()`, `to_data()`.

#### Theme

* атрибуты: `id`, `name`, `content` (текст темы, простая строка);
* методы: `__str__()`, `from_data()`, `to_data()`.

#### Progress

* атрибуты: `id`, `user`, `course`, `completed_theme_ids`;
* методы: `mark_theme_completed()`, `is_theme_completed()`,
  `calculate_percent()`, `__str__()`, `to_data()`.

## Страницы веб-интерфейса

* `/` – главная страница, навигация (`homepage.views.index()`);
* `/courses/` – список курсов из `data/courses.json`
  (`catalog.views.course_list()`);
* `/courses/<int:course_id>/` – страница курса со списком тем
  (`catalog.views.course_detail()`);
* `/courses/<int:course_id>/themes/<int:theme_id>/` – страница темы: текст,
  кто прошёл, кнопка «Отметить пройденной» для вошедшего студента
  (`catalog.views.theme_detail()`);
* `/courses/<int:course_id>/themes/<int:theme_id>/complete/` – POST-запрос
  отметки темы пройденной; GET даёт 405, без входа – переход на `/login/`
  (`catalog.views.theme_complete()`);
* `/progress/` – список прогресса пользователей
  (`progress.views.progress_list()`);
* `/progress/<int:progress_id>/` – карточка прогресса: пользователь, курс,
  процент, статус каждой темы (`progress.views.progress_detail()`);
* `/login/` – вход по имени студента (`accounts.views.login_view()`);
* `/logout/` – выход (`accounts.views.logout_view()`);
* `/my/` – мои курсы и личный прогресс вошедшего студента; без входа
  перенаправляет на `/login/` (`accounts.views.my_courses()`).

### Вход по имени

Авторизация намеренно упрощена: на странице `/login/` вводится имя студента
из `data/users.json` (регистр и пробелы по краям не важны). Пароля нет.
Идентификатор студента хранится в сессии на подписанных cookie
(`SESSION_ENGINE = "...signed_cookies"`), поэтому база данных не нужна.
В меню вошедший студент отображается рядом со ссылкой «Выйти». В данных два
студента: «Студент» и «Анна».

Если курс, тема или прогресс с указанным идентификатором не найден,
страница возвращает код статуса 404. Для любых несуществующих адресов
используется собственный обработчик `handler404`
(`homepage.views.page_not_found()`).

Сущность `User` из ПР3 используется как студент: по ней выполняется вход
и показывается личный прогресс. Встроенная модель `django.contrib.auth.User`
пока не задействована – полноценная аутентификация будет в следующих работах.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка курсов, курса и темы;
* отметка темы пройденной (`mark_theme_completed()` из ПР3);
* просмотр списка прогресса и карточки прогресса;
* расчёт процента прохождения (`Progress.calculate_percent()`).

### Доступно в консольной версии (ПР3)

Эти операции пока доступны только в консоли и появятся в вебе вместе с
формами:

* добавление курса;
* поиск курсов по названию;
* отбор курсов по минимальному прогрессу;
* сортировка курсов по прогрессу.

## Хранение данных

Данные хранятся в JSON-файлах каталога `data/`:

* `data/courses.json` – курсы и темы;
* `data/users.json` – пользователи;
* `data/progress.json` – прогресс пользователей.

Формат курса в `data/courses.json` (у каждой темы есть текст `content`):

```json
{
  "1": {
    "name": "Разработка на Python",
    "themes": [
      {"id": 1, "name": "Переменные", "content": "Текст темы."}
    ]
  }
}
```

При отметке темы в вебе обновляется `data/progress.json`: для студента
создаётся запись `Progress` (если её ещё нет по этому курсу) или в неё
добавляется `id` темы в `completed_theme_ids`. Повторная отметка безопасна.

При загрузке данные преобразуются в объекты `Course`, `Theme`, `User` и
`Progress`, при сохранении – обратно в JSON. Веб-слой читает данные через
`homepage/data.py` (`load_all()`), используя функции `storage.py` из ПР3.
Переход на Django ORM и базу данных запланирован на следующие работы.

```text
├── storage.py       – загрузка и сохранение JSON
├── utils.py         – безопасный ввод для консоли
│
├── tracker/         – конфигурация Django-проекта
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   └── wsgi.py
│
├── homepage/        – главная страница, общий HTML-каркас, страница 404
│   ├── data.py      – загрузка данных ПР3, текущий студент из сессии
│   ├── urls.py
│   └── views.py
├── accounts/        – вход по имени, выход, «Мои курсы»
│   ├── urls.py
│   └── views.py
├── catalog/         – курсы и темы
│   ├── urls.py
│   └── views.py
├── progress/        – прогресс пользователей
│   ├── urls.py
│   └── views.py
│
├── models/          – классы предметной области (ПР3)
│   ├── user.py
│   ├── course.py
│   ├── theme.py
│   └── progress.py
├── data/            – JSON-хранилище
└── tests/
    ├── test_courses.py  – тесты консольной части (ПР3)
    ├── conftest.py      – тесты работают с временной копией data/
    ├── test_web.py      – тесты веб-интерфейса (ПР5)
    ├── test_login.py    – тесты входа по имени
    └── test_themes.py   – тексты тем и отметка пройденных тем
```

Приложение для курсов названо `catalog`, а не `courses`, потому что в корне
проекта уже есть модуль `courses.py` (ПР3), и одноимённый пакет сломал бы
его импорт. Файлы `models.py`, `admin.py`, `tests.py` в приложениях
пока пустые – Django-модели появятся на следующих работах. Не следует
путать `models.py` приложений с пакетом `models/` (классы ПР3).

## Назначение основных view-функций

| Функция | Файл | Назначение |
|---|---|---|
| `page()` | `homepage/views.py` | единый HTML-каркас: Bootstrap 5.3, навигация, вошедший студент |
| `not_found()` | `homepage/views.py` | страница с сообщением и кодом 404 |
| `login_view()` | `accounts/views.py` | вход по имени студента |
| `logout_view()` | `accounts/views.py` | выход |
| `my_courses()` | `accounts/views.py` | мои курсы и личный прогресс |
| `index()` | `homepage/views.py` | главная страница `/` |
| `page_not_found()` | `homepage/views.py` | обработчик `handler404` |
| `course_list()` | `catalog/views.py` | список курсов |
| `course_detail()` | `catalog/views.py` | страница курса |
| `theme_detail()` | `catalog/views.py` | страница темы с текстом и кнопкой отметки |

`find_progress_by_id()`, `find_user_by_id()`, `find_user_by_name()`
(`courses.py`) и `Course.get_theme_by_id()`.

## Запуск приложения

Подготовка окружения (Windows):

```text
py -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
```

Веб-версия (Django):

```text
python manage.py runserver
```

После запуска открыть в браузере `http://127.0.0.1:8000/`.

Консольная версия (сохранена):

```text
python main.py
```

## Текущее состояние и план развития

Реализовано (ПР5):

* Django-проект `tracker` и четыре приложения (`homepage`, `accounts`,
  `catalog`, `progress`);
* вход по имени студента и страница «Мои курсы»;
* тексты тем и отметка тем пройденными через веб;
* маршрутизация URL двух уровней, динамические адреса с `<int:...>`;
* view-функции и страницы на HTML и Bootstrap 5.3;
* отображение данных всех четырёх сущностей (`Course`, `Theme`, `User`,
  `Progress`) из JSON-хранилища ПР3;
* навигация между страницами и собственная страница 404.

Планируется:

* настоящая аутентификация (пароли, `django.contrib.auth`) вместо входа по имени;
* шаблоны Django (`templates/`) вместо функции `page()`;
* перенос сущностей в Django ORM и подключение базы данных;
* формы и отложенная логика ПР3 (добавление курса, отметка темы);
* API, контейнеризация, CI/CD.
